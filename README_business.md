# Поступашки — Marketing Measurement System

Система измерения эффективности маркетинга в Telegram: от рекламного размещения до заявки, оплаты и ROMI.

## Зачем это бизнесу

До внедрения системы продажи были видны, а путь клиента до покупки — нет.  
Поэтому нельзя было уверенно ответить на вопросы:

- какое размещение приносит деньги;
- где реклама окупается;
- куда направить следующий маркетинговый бюджет;
- какая часть продаж пришла органически.

Мы построили MVP, который начинает собирать недостающую цепочку:

**размещение → переход → интерес → заявка → оплата → атрибуция → ROMI**

## Что уже работает

Telegram-бот одновременно является:

- точкой входа клиента по рекламной ссылке;
- интерфейсом менеджера для фиксации заявок и оплат;
- интерфейсом маркетолога для создания размещений;
- источником отчётов по воронке, CPA и ROMI.

Маркетолог задаёт канал, кампанию, стоимость и дату размещения.  
Бот создаёт уникальную ссылку и дальше связывает рекламное касание с действиями пользователя и оплатой.

## Что получает маркетолог

По каждому размещению можно увидеть:

- сколько пользователей пришло;
- сколько посмотрело продукт;
- сколько оставило заявку;
- сколько оплатило;
- стоимость размещения;
- приписанную выручку;
- CPA;
- ROMI.

При этом система разделяет:

**Факты** — переходы, заявки, оплаты, затраты.  
**Оценки модели** — attribution, приписанная выручка и ROMI.

## Атрибуция

В MVP реализованы четыре модели:

- `last` — 100% выручки последнему касанию;
- `first` — 100% первому;
- `linear` — выручка делится между всеми касаниями;
- `position` — больший вес первому и последнему касанию.

Общие правила:

- окно атрибуции — 30 дней;
- после покупки история рекламных касаний для следующей покупки начинается заново;
- если подходящих рекламных касаний нет, продажа относится к `Organic/Direct`.

Мы не считаем одну attribution-модель «истиной».  
Если бизнес-вывод сохраняется при разных моделях, решение считаем более устойчивым.

## ROMI

Для платных размещений:

**ROMI = (приписанная выручка − стоимость рекламы) / стоимость рекламы**

Дополнительно можно учитывать комиссию эквайринга и считать ROMI по марже.

Важно: attribution показывает, **кому модель приписала уже случившуюся продажу**, но не доказывает, что продажа появилась именно благодаря рекламе. Для оценки реального incremental effect нужен holdout / A/B / другой causal-дизайн.

## Какие данные используются

В проекте есть:

- реальные обезличенные продажи;
- публичная история собственного Telegram-канала;
- данные, которые собирает бот;
- synthetic/mock данные для демонстрации и тестирования measurement system.

Исторический ROMI внешней рекламы корректно восстановить нельзя: в прошлых данных нет полной связи между рекламным источником и покупателем, а также полного списка размещений и их стоимости.

Поэтому synthetic-данные используются не как замена реальным результатам, а как **контрольный эксперимент для проверки логики attribution engine**.

## Synthetic experiment

Отдельный эксперимент находится в:

`notebooks/synthetic_attribution_experiment_colab.ipynb`

Он:

- калибруется по историческим продажам;
- сохраняет сезонный профиль спроса;
- моделирует небольшой incremental effect рекламы;
- знает скрытый ground truth;
- сравнивает attribution-модели по качеству ранжирования рекламных размещений и ошибке ROMI.

Подробное описание: [`notebooks/README_experiment.md`](notebooks/README_experiment.md)

## Структура MVP

```text
src/
├── bot/main.py          # Telegram-интерфейс
└── core/
    ├── db.py            # база и запись событий
    ├── attribution.py   # attribution + ROMI
    ├── importer.py      # импорт продаж
    └── quality.py       # контроль полноты данных

data/
├── raw/                 # исходные реальные данные
├── processed/           # обработанные данные
└── mock/                # synthetic/mock данные

notebooks/
├── EDA.ipynb
└── synthetic_attribution_experiment_colab.ipynb
```

## Как запустить

```bash
pip install -r requirements.txt
cp .env.example .env
python -m bot.main
```

Основные команды маркетолога:

- `/newlink` — создать рекламное размещение;
- `/links` — посмотреть активные ссылки;
- `/report` — получить воронку и ROMI;
- `/status` — проверить полноту данных;
- `/import` — загрузить историю продаж.

## Главный результат

Проект не пытается «угадать» прошлый маркетинг по неполным данным.

Он создаёт процесс, в котором **каждое новое рекламное размещение становится измеримым**, а решение о следующем бюджете можно принимать на основе фактов, attribution и последующих causal-экспериментов.
