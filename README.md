# Поступашки — Marketing Measurement System

MVP для сбора маркетинговых касаний, заявок и оплат и расчёта attribution / ROMI.

Исторические данные используются для EDA. Для новых рекламных запусков Telegram-бот создаёт tracking-ссылки и собирает недостающий путь пользователя до покупки.

## Карта проекта

```text
hackaton_project/
├── README.md
├── requirements.txt
├── data/
│   ├── raw/          # исходные продажи и Telegram-посты

```

## Запуск Telegram-бота

### 1. Установить зависимости

```bash
pip install -r requirements.txt
```

### 2. Настроить `.env`

```bash
cp .env.example .env
```

Заполнить:

```text
BOT_TOKEN=...
ADMIN_IDS=...
MANAGER_CHAT_ID=...
MANAGER_IDS=...
MANAGER_USERNAME=...
HASH_SALT=...
ACQUIRING_RATE=0.03
ATTRIBUTION_WINDOW_DAYS=30
```

`BOT_TOKEN`, `HASH_SALT`, `.env` и `data/bot.db` не должны попадать в GitHub.

### 3. Запустить

Из корня проекта:

```bash
cd src
python -m bot.main
```

SQLite-база создаётся автоматически в `data/bot.db`.

## Как пользоваться ботом

Маркетолог открывает `/menu`. Основной сценарий:

1. `/newlink` — создать рекламное размещение: канал, кампания, стоимость, дата, тип поста.
2. Бот выдаёт отдельную tracking-ссылку для этого размещения.
3. Пользователь переходит по ссылке и запускает бота. Система сохраняет источник и его действия в боте.
4. Если пользователь пришёл без рекламной метки, бот спрашивает, откуда он узнал о продукте.
5. После заявки менеджер проводит продажу и записывает оплату через `/paid`.
6. `/report` — получить воронку, затраты, attributed revenue, CPA и ROMI.

### Команды маркетолога

| Команда | Что делает |
|---|---|
| `/menu` | панель управления |
| `/newlink` | создать размещение и tracking-ссылку |
| `/links` | история размещений и ссылок |
| `/report [модель]` | воронка, затраты, CPA, attributed revenue и ROMI |
| `/status` | проверить полноту данных |
| `/import` + файл | импортировать `base.xlsx` / `base.csv` |
| `/paid № сумма курсы` | записать оплату по заявке |
| `/export` | выгрузить базу |

Доступные модели для `/report`: `last`, `first`, `linear`, `position`.

## Что собирает MVP

Система связывает:

**размещение → пользователь → действия в боте → заявка → оплата**

Для каждого размещения маркетолог может увидеть историю кампании, стоимость и дату, измеримые заходы и просмотры, заявки, оплаты и рассчитанный ROMI.

Первый измеримый шаг — **нажатие «Старт» в Telegram**. Сам клик по ссылке без запуска бота Telegram не передаёт.

## Исторические данные и эксперимент

`EDA.ipynb` работает с реальными историческими продажами и Telegram-постами. Он нужен для анализа спроса, сезонности и контента; исторический источник каждой покупки по этим данным восстановить нельзя.

Synthetic experiment находится отдельно в `notebooks/`. Он генерирует пользователей, касания и покупки с известным ground truth и используется для проверки того, как четыре attribution-модели ведут себя при multi-touch, органическом спросе, повторных покупках и сезонности.

Mock/synthetic данные не смешиваются с реальными без соответствующей маркировки.
