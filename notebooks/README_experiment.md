# Synthetic attribution experiment

Эксперимент проверяет attribution engine в контролируемой среде, где мы заранее знаем, **какие продажи возникли органически, а какие были добавлены рекламой**.

Файл эксперимента: `synthetic_attribution_experiment_colab.ipynb`.

## Какие данные мы генерируем

Базовый запуск создаёт **1 000 synthetic-пользователей** на временном интервале, соответствующем периоду исторических продаж.

Для каждого пользователя моделируются четыре типа данных:

| Данные | Что генерируется |
|---|---|
| Пользователь | synthetic ID и индивидуальная склонность к покупке |
| Рекламные касания | переходы из placements A/B/C/D в разные даты |
| Поведение в боте | часть пользователей после входа просматривает курс |
| Продажи | 0, 1 или максимум 2 заказа с суммой, временем и hidden ground truth |

Суммы заказов не задаются одной константой: они семплируются из распределения реальных исторических заказов. Временной baseline спроса также строится по исторической динамике продаж.

## Как устроены рекламные касания

В эксперименте есть четыре synthetic-размещения: `A`, `B`, `C`, `D`. Они отличаются стоимостью, охватом, временем публикации и скрытым рекламным эффектом.

Пользователь может:

- вообще не получить paid advertising touch;
- получить одно рекламное касание;
- взаимодействовать с несколькими placements;
- после первой покупки получить новое касание и потенциально совершить повторную покупку.

То есть в данных **есть настоящий multi-touch**.

Вероятность касания немного выше у пользователей с большей скрытой склонностью к покупке. Это намеренно создаёт selection effect: аудитория рекламы не является идеально случайной.

После генерации notebook сам показывает фактическое распределение:

- `0 / 1 / 2 / 3+` рекламных касаний;
- среднее, медиану и максимум касаний;
- долю пользователей с `2+` касаниями;
- долю пользователей с `2+` разными placements.

Конкретные проценты не фиксируются в README вручную: они автоматически считаются для текущего seed, чтобы документация не расходилась с результатом генератора.

## First touch и Last touch

Для каждого пользователя с рекламой notebook определяет:

- **First touch** — первое paid advertising касание;
- **Last touch** — последнее paid advertising касание перед окончанием наблюдения.

Строятся:

1. распределения first и last touch по `A/B/C/D`;
2. матрица **First touch → Last touch**.

Диагональ матрицы показывает пользователей, у которых первый и последний placement совпадают. Ячейки вне диагонали показывают multi-placement paths, например:

`A → B`, `A → D`, `B → C`.

Это позволяет увидеть, насколько задача действительно является multi-touch, прежде чем сравнивать attribution-модели.

## Как пользователи покупают

Покупка моделируется в два этапа.

### 1. Organic / seasonal demand

Сначала рассчитывается вероятность естественной покупки.

Она зависит от:

- исторического профиля спроса;
- даты;
- индивидуальной склонности пользователя к покупке;
- того, является ли покупка первой или повторной.

Именно organic/seasonal demand создаёт основную часть продаж.

### 2. Incremental advertising lift

Если органическая покупка в этот день не произошла, реклама может создать дополнительную вероятность покупки.

Эффект рекламы:

- небольшой относительно естественного спроса;
- зависит от placement;
- уменьшается с количеством дней после касания;
- действует только внутри attribution window.

Если рекламный эффект действительно создаёт заказ, генератор сохраняет его `true_driver`.

Поэтому для каждого заказа мы знаем:

`organic` **или** `ad_incremental`.

Эту информацию attribution engine не получает.

## Сколько пользователей покупают

Notebook автоматически рассчитывает:

- число и долю пользователей хотя бы с одной покупкой;
- долю пользователей без покупок;
- число заказов;
- долю повторных покупателей;
- долю organic orders;
- долю ad-incremental orders;
- средний и медианный чек.

Дополнительно строится:

**Purchase rate для пользователей с 0 / 1 / 2 / 3+ рекламных касаний.**

Это позволяет проверить, какое поведение фактически получилось у synthetic population, а не делать вывод только из параметров генератора.

Важно: эти показатели являются характеристиками **симуляции**, а не оценкой реальной конверсии клиентов «Поступашек».

## Зачем нужна сезонность

Рекламные placements намеренно могут располагаться рядом с периодами высокого естественного спроса.

Получается реалистичная ситуация:

**реклама → вскоре покупка**

но часть таких покупателей купила бы продукт и без рекламы.

Rule-based attribution видит последовательность событий и может дать рекламе credit. Генератор при этом знает, была покупка organic или действительно incremental.

Именно на этом конфликте мы стресс-тестируем attribution.

## Что является ground truth

Для каждой synthetic-покупки скрыто сохраняется:

- тип покупки: `organic` / `ad_incremental`;
- placement, который действительно создал incremental purchase;
- сумма заказа.

Поэтому для каждого placement можно рассчитать:

**True incremental revenue = выручка от заказов, действительно добавленных этим placement**

и

**True incremental ROMI = (incremental revenue − advertising cost) / advertising cost.**

Это causal ground truth нашего synthetic-мира.

## Какие attribution-модели сравниваются

Используется тот же `src/core/attribution.py`, что и в Telegram-боте:

| Модель | Распределение выручки |
|---|---|
| `last` | всё последнему касанию |
| `first` | всё первому |
| `linear` | поровну между касаниями |
| `position` | больший вес первому и последнему |

Общие production-правила:

- attribution window — 30 дней;
- после покупки старые касания не участвуют в attribution следующей покупки;
- если подходящих paid touches нет, заказ относится к `Organic/Direct`.

## Как оцениваем модели

Мы сравниваем attribution ROMI с известным synthetic ground truth.

Используются четыре основные метрики:

| Метрика | Бизнес-смысл |
|---|---|
| Top-1 accuracy | как часто модель выбирает действительно лучший placement |
| Rank correlation | правильно ли модель ранжирует рекламные размещения |
| ROMI MAE | насколько сильно ошибается в величине ROMI |
| Sign accuracy | правильно ли определяет `окупается / не окупается` |

Дополнительно смотрим bias: не завышает ли модель ROMI систематически из-за organic/seasonal demand.

Эксперимент повторяется на нескольких random seeds, поэтому итог не зависит от одного удачного synthetic-прогона.

## Какие визуализации строятся

Notebook автоматически создаёт:

1. **исторический demand profile** — какой baseline спроса использует генератор;
2. **распределение 0 / 1 / 2 / 3+ touches**;
3. **purchase rate vs число рекламных касаний**;
4. **First touch → Last touch matrix**;
5. **распределение first и last touch по placements**;
6. **True incremental ROMI vs attribution ROMI**;
7. **сравнение моделей по rank correlation**;
8. **сравнение моделей по sign accuracy**.

Таким образом сначала можно проверить, что synthetic population выглядит разумно, и только после этого интерпретировать результат attribution experiment.

## Как интерпретировать результат

Цель эксперимента — **не выбрать универсально лучшую attribution-модель**.

Мы проверяем:

- какая модель лучше ранжирует placements в выбранном сценарии;
- насколько результат устойчив к multi-touch;
- насколько сезонность приводит к переоценке рекламы;
- меняется ли бизнес-решение при смене attribution-модели.

Если несколько моделей дают одинаковый вывод по placement, решение устойчивее.

Если `first / last / linear / position` приводят к разным решениям, одного attribution недостаточно для уверенного перераспределения бюджета.

Откройте:

## Ограничение эксперимента

Synthetic ground truth известен только потому, что механизм генерации задали мы сами.

Поэтому хороший результат модели в симуляции не доказывает causal effect рекламы в реальном бизнесе.

**Attribution ≠ incrementality.**

Следующий шаг для реальных кампаний — holdout, randomized promotion, A/B-тест или другой causal design.
